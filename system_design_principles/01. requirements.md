# 1. Requirements

Functional and non-functional requirements

- Functional: What it does?
- Nonfunctional: How it does?

- You must here define the boundaries
  - Scale and scope

- Example: URL shortner
  - Functional: create short links, redirect to long links
  - Non-functional: high availability (redirects shouldn't fail), low latency, 10k requests/second

## Common Systems

### 1. "Read-heavy": Twitter/IG | high distribution & low-latency

This systems tests you ability to design a system with `massive fan-out` (big data distribution) and low-latency reads

- fan-out: taking a piece of data and delivering to a massive number of destinations
  - replicating/propagating the data in a huge scale in a short time

- Functional:
  - post a tweet/post
    - text
    - image
  - read a tweet/post
  - follow others
  - followed by others
  - timeline
- Non-functional:
  - availability > consistency
    - high-availability: should have an extremely low time down
    - if it takes a while for the data to propagate it's fine, but the system shouldn't be down
  - low-latency:
    - reading should be fast
    - timeline should be fast

Concepts

- Which 'fan-out' should you opt?
  - do you "push" tweets to every follower's inbox? (write-heavy)
  - do you "pull" tweets when a user logs in? (read-heavy)
- how do you handle celebrities? ("thundering herd" problem)
  - thundering herd = some trigger (single event) that causes a large number of processes/threads, or servers to "wake up"/operate simultaneously, what can overwhelm a system

### 2. "Write-heavy": Metrics/logging (datadog) | storage engines & high-throughput

This system tests your knowledge of storage engines and high-throughput ingestion

- High-throughput ingestion: ability of a system to receive, process, and store massie volumes of data (often millions of events per second)

- Functional:
  - Record metrics (CPU, memory) from millions of servers
  - Query metrics for graphs/analytics

- Non-functional:
  - high write throughput
    - must never drop a metric
    - data compression: storing billions of data points is expensive
  - consistency > availability

Concepts:

- LSM-trees
- SSTables
